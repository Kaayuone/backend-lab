[Основной маршрут](README.md) · [Этапы](ROADMAP.md) · [Трекер](tracker.html)

План создан 2 октября 2026 года. Учебные результаты пока не подтверждены диагностикой;
старые отметки о завершении этапов не перенесены автоматически.

## Принятые решения

- Цель: свои SaaS и мобильные продукты; fullstack/backend как дополнительный карьерный путь.
- Основной язык: TypeScript; Go/Python позже по задаче.
- Темп: до 10 часов в неделю, с механизмами и экспериментами.
- Рынок для возможного найма: русскоязычный, предпочтительно удалённая работа.
- Практика: разные предметные области; обязательный личный Telegram-бот для аудио.
- Повторяющийся каркас можно переносить, интерфейс — генерировать с AI.

## Первые две недели

Это стартовая раскладка на 20 часов, а не обещание завершить этап SQL за две недели.

1. **2 часа:** диагностический SQL/HTTP-разбор без AI. Записать, что удалось и где были подсказки.
2. **4–6 часов:** отдельная учебная/тестовая БД, подключение, проверка volume и команды запуска.
   Этап 0 суммарно занимает 6–8 часов.
3. **4 часа:** модель Spendboard, выбор типов и ограничений, первая миграция.
4. **4 часа:** JOIN и агрегации по тестовым данным, проверка пустых и пограничных случаев.
5. **4–6 часов:** транзакция с искусственным отказом, дополнительные SQL-задачи,
   короткая запись ошибок и корректировка дальнейшей оценки. Взять оставшееся время из 20 часов.

Если диагностика подтверждает уверенный навык, переходить к следующей задаче.
Если текущие инструменты уже настроены безопасно, повторная установка не нужна.

## Шаблон записи после темы

```text
Дата / тема:
Потрачено времени:
Задача и ожидаемое поведение:
Что сделал самостоятельно:
Где помогли документация / AI:
Какой отказ воспроизвёл:
Результат и доказательство:
Что ещё не понял:
Следующее небольшое действие:
```

После 20–30 часов сравнить факт с оценкой. После каждого проекта проверить, сохранилась ли
практическая польза и не вырос ли объём за пределы задания. Пересматривать темп и предметную
область можно; пропускать непонятные инварианты ради формальной галочки не следует.

## Трекер

[tracker.html](tracker.html) — рабочий инструмент для текущих отметок: пункты этапов, статусы
с доказательством, приёмка проектов и журнал занятий по шаблону выше. Открывается в браузере
без сервера; из корня репозитория:

```powershell
Start-Process docs/backend-learning/tracker.html
```

Отметки хранятся в localStorage браузера и в git не попадают. Для переноса и резервной копии
есть кнопки «Скачать копию» и «Восстановить из копии». Этот файл остаётся основной записью
подтверждённого прогресса: после проверки этапа таблица «Контрольные точки» обновляется
из трекера кнопкой «Таблица для PROGRESS.md».
