[К границам и оценке времени](README.md) · [Стек](STACK.md) · [Проекты](PROJECTS.md) · [Прогресс](PROGRESS.md)

Порядок построен по зависимостям навыков. Критерии выхода проверяют самостоятельность,
а не число просмотренных уроков. Все оценки включают реализацию соответствующей части проекта.
Проекты описаны отдельно, чтобы требования к приложению не повторялись в каждом этапе.

Каждый этап описан в отдельном файле каталога [stages](stages/).

## Как устроен файл этапа

Каждый файл повторяет одну структуру:

- **Зачем этот этап** — какую проблему решает этап и что в ней нового после фронтенда.
- **Что разобрать** — механизмы с объяснением, примерами и ссылками на документацию.
- **Сделать** — задания этапа с подсказками, что проверить.
- **Эксперименты** — что воспроизвести и какое наблюдение ожидается.
- **Критерии выхода** — что нужно уметь без подсказки.
- **Типичные ошибки** и **что записать как доказательство**.

Задания, эксперименты и критерии выхода совпадают с пунктами [трекера](tracker.html).
Подсказки описывают механизмы и проверки, но не готовые решения: новый SQL-запрос, транзакцию,
правило доступа и обработку webhook сначала нужно спроектировать самостоятельно
(см. [README.md](README.md#как-использовать-ai-и-готовые-решения)).

## Общие правила

- Цикл новой темы: сформулировать проблему → предсказать поведение → реализовать →
  воспроизвести отказ → объяснить наблюдение → закрепить важный контракт тестом.
- Документацию читать по теме текущего задания; читать все источники заранее не нужно.
- Этап отмечается пройденным только вместе с доказательством, см. [PROGRESS.md](PROGRESS.md).
- Если критерии этапа уже выполняются на текущем коде, этап сокращается.

## После обязательного маршрута

Выбирать одно расширение по реальному продукту: SSE/WebSocket, поиск средствами PostgreSQL,
mobile push, полноценная подписка, OIDC-провайдер, offline-sync, Go-сервис, Python-обработка.
Каждое расширение начинается с задачи, ограничений и критерия результата.

Для поиска работы добавить подготовку по выбранным вакансиям: SQL-задачи, объяснение
архитектуры, диагностика инцидента, интервью по runtime и необходимый уровень алгоритмов.
Это отдельный трек; основной план оптимизирован под самостоятельное создание продуктов.
