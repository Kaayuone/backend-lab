# Этап 7. Файлы и внешние интеграции

[Маршрут](../ROADMAP.md) · [← Этап 6](06-telegram-queue-worker.md) · [Этап 8 →](08-deploy-operations.md)

**Оценка:** 16–22 часа. **Проект:** [Audio Bot](../PROJECTS.md#проект-2-audio-bot--личный-telegram-бот-для-аудио),
лабораторная загрузки и email для Spendboard. **Нужно до начала:** авторизация этапа 4,
worker этапа 6.

**Результат:** надёжная выдача файлов и email-адаптер.

**Цель:** перестать считать внешнюю систему надёжной частью собственного процесса.

## Зачем этот этап

Внешняя система отказывает иначе, чем собственный код: отвечает 429, рвёт соединение после
получения запроса, меняет формат ответа, удаляет файл до выдачи. Файлы добавляют свои вопросы:
где хранить содержимое и метаданные, кто может скачать, когда удалять, как найти объекты,
о которых забыла БД. Этап учит держать внешний сервис за небольшим адаптером с явными лимитами.

## Что разобрать

### Объектное хранилище

Bucket, ключ объекта, метаданные. Содержимое лежит в object storage, а владелец, имя для
пользователя и срок жизни — в PostgreSQL. Bucket приватный; доступ выдаётся после проверки прав
короткой подписанной ссылкой (presigned URL). Срок хранения задаётся правилом жизненного цикла
и проверяется уборкой. Для локальной разработки подходит любое S3-совместимое хранилище;
перед выбором проверить его текущую лицензию и статус поддержки.

Документация: [presigned URL в S3](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html),
[жизненный цикл объектов](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lifecycle-mgmt.html).

### Прямая загрузка

Сервер согласует размер, тип и ключ, выдаёт ссылку на загрузку, клиент загружает файл напрямую
в хранилище. После загрузки сервер проверяет фактический объект (размер, тип по содержимому)
и только затем публикует его. Заголовок `Content-Type` от клиента — заявление, а не факт.
Неподтверждённые загрузки удаляются по сроку.

Документация: [OWASP File Upload](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html).

### Скачивание

Файл передаётся потоком, а не читается целиком в память. Ключ объекта случайный: по имени файла
нельзя угадать чужой ключ. Имя для пользователя передаётся в `Content-Disposition` с учётом
не-ASCII символов.

Документация: [Content-Disposition](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Disposition),
[`stream.pipeline`](https://nodejs.org/api/stream.html).

### Email

Отправка писем скрыта за адаптером. Тесты используют fake, локальная разработка — перехватчик
писем, а отдельный smoke-тест проверяет настоящий транспорт.

Документация: [Nodemailer](https://nodemailer.com/), [Mailpit](https://mailpit.axllent.org/) —
пример локального перехватчика писем.

### Политика HTTP-клиента

Общий клиент задаёт таймауты, число попыток и конкурентность. Ответ 429 обрабатывается
с учётом `Retry-After`. Повторяются безопасные и идемпотентные запросы; повтор неидемпотентного
требует ключа идемпотентности или другого решения. Ответ внешнего API проверяется по схеме
до использования.

Документация: [429](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/429),
[Retry-After](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Retry-After),
[undici](https://undici.nodejs.org/) — HTTP-клиент, на котором основан `fetch` в Node.js.

### SSRF

Если сервер скачивает данные по URL от пользователя, злоумышленник может направить его
во внутреннюю сеть или к metadata endpoint облака. Проверка строки URL недостаточна: адрес
меняется после редиректа или DNS-разрешения. Нужны allowlist схем и хостов, проверка IP-адреса
после разрешения имени и контроль редиректов.

Документация: [OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).

## Сделать

1. Добавить временный приватный архив результатов Audio Bot в S3-совместимом хранилище.
   Метаданные и владелец — в PostgreSQL, содержимое — в object storage, у объекта есть срок
   жизни. Доступ выдаётся после авторизации через короткую подписанную ссылку.
2. Пройти маленькую лабораторную прямой загрузки: согласовать размер/тип/ключ, проверить
   фактический объект перед публикацией; очистить загрузку, для которой пользователь так и
   не завершил подтверждение. Не доверять одному Content-Type клиента.
3. Для скачивания не читать целый файл в память. Разобрать имя файла, случайный object key,
   Content-Disposition, ограничения размера и приватность bucket.
4. Подключить email-транспорт для готового восстановления доступа из [этапа 4](04-auth-security.md).
   Проверки приложения используют fake/sink, отдельный smoke проверяет настоящий транспорт.
5. В общем HTTP-клиенте ограничить время, число попыток и конкурентность; учитывать
   429/Retry-After. Повтор неидемпотентного запроса требует отдельного решения.
6. Проверить SSRF и опасность произвольного URL: scheme/host, редиректы, DNS, доступ
   к loopback/private/link-local адресам. Одной проверки строки URL недостаточно.

## Эксперименты

1. **Файл удалён до выдачи.** Пользователь получает понятный ответ, метаданные приводятся
   в соответствие.
2. **Подписанная ссылка истекла.** Доступ закрыт; новая ссылка выдаётся только после проверки прав.
3. **Сервис отвечает 429.** Клиент ждёт по `Retry-After` и не превышает число попыток.
4. **Соединение оборвалось после отправки запроса.** Неизвестно, выполнил ли сервис операцию;
   записать, как код ведёт себя в этом случае.
5. **Внешний ответ не соответствует ожидаемой схеме.** Ошибка распознаётся на границе адаптера,
   а не в глубине бизнес-логики.

## Критерии выхода

- Умеешь разделить ошибку транспорта и доменный отказ.
- Ограничиваешь стоимость операции.
- Не выдаёшь чужие файлы.
- Есть способ убрать бесхозные объекты.

Провайдер хранится за небольшим адаптером, а не за универсальной абстракцией всех облаков.

## Типичные ошибки

- Публичный bucket или файлы в БД.
- Доверие к `Content-Type` и имени файла от клиента.
- Подписанная ссылка на часы и дни или выданная без проверки прав.
- Чтение всего файла в память при скачивании.
- Автоматический повтор `POST` без ключа идемпотентности.
- Проверка URL только по строке.

## Что записать как доказательство

Тест выдачи чужого файла (отказ), результаты пяти экспериментов, сценарий уборки бесхозных
объектов, smoke-проверка email-транспорта.
